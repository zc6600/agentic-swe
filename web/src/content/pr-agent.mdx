# PR Agent

The PR Agent attempts straightforward conflict repairs, validates them, and produces **`result.json` plus `repair.patch`**. It never commits, pushes, opens pull requests, or merges. You decide whether and how to publish the patch.

**For maintainers:** Add only `OPENROUTER_API_KEY`; no GitHub write token is required. The default reusable workflow runs for same-repository PRs only.

<details id="maintainer-setup">
<summary>Maintainer setup</summary>

1. Add `OPENROUTER_API_KEY` under **Settings → Secrets and variables → Actions**.
2. Install the workflow below, replacing `npm test` with a real test command.
3. Find the JSON and patch in the workflow run artifacts. A clean PR skips the model in `conflict-only` mode.

```yaml
name: PR Agent

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read
  pull-requests: read

jobs:
  agent:
    uses: zc6600/agentic-swe/.github/workflows/pr-agent.yml@main
    with:
      validation-command: npm test
      trigger-on: conflict-only
    secrets:
      OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
```

<details id="agent-integration">
<summary>Instructions for coding agents</summary>

Copy these instructions into your coding agent. Secret values must only be added by maintainers.

```text
Integrate the output-only PR Agent into this repository.

1. Inspect existing workflows and identify a meaningful test command.
2. Add .github/workflows/pr-agent.yml using the example from docs/pr-agent.md.
3. Configure permissions as contents: read and pull-requests: read.
4. Ask the maintainer to set OPENROUTER_API_KEY; no PR_AGENT_TOKEN is needed.
5. The workflow produces result.json and repair.patch. Do not add GitHub push or merge actions to the Agent.
6. Default fork PRs are skipped; external PR code needs a separately isolated worker.
7. Validate the workflow and explain how to inspect artifacts.

Never use `true` in place of tests. Pin workflow references to a reviewed release/commit in production.
```

**Security:** A `PASS` verdict is not merge approval. A separate trusted publisher must independently verify the patch, base/head SHAs and CI. Do not run untrusted fork code in a privileged `pull_request_target` job.
